# 人體訓練地圖 v3 — 呈現與計算契約

本版回答三個不同問題：「這次練到哪裡」「期間累積多少」「哪些相關動作有進步」。用同一人體座標切換圖層，每一層的顏色只有一種意義，數字與來源紀錄供核對。原創 SVG 細分 15 個區域，正背面、肌束輪廓、部位標線與可選骨架；手機將圖放大，明細置於圖下。

## 使用方式與色彩

| 視圖 | 範圍與操作 | 顏色意義 |
|---|---|---|
| 本次訓練 | 選日期，再選當日全部或一筆紀錄；也可篩動作／器材 | 青色主要關聯、紫色協同、灰色無紀錄 |
| 期間累積 | 使用概覽日期範圍與動作／器材篩選 | 青色深淺為主要關聯組數 1–4、5–9、10+；紫色僅協同，灰色無紀錄 |
| 可比進步 | 每個動作／器材／單位獨立比較最近兩筆 | 青色進步、灰藍持平、橘色下降、紫色不一致、黃褐需檢視、淺灰資料不足 |

進步模式同時提供文字與箭頭；色彩不是唯一識別方式。選取外框不改原本數值色。日期是紀錄日期；同日可能有多次實際訓練，目前沒有獨立 workout ID，所以介面明稱「當日全部紀錄／單筆紀錄」。

累積色階分界只為固定、可重現的視覺分級，不是有效組數、建議訓練量或安全上限。長條使用當前篩選的最大主要組數為共同尺度，顯示精確主要／協同組數。沒有跨器材比較公斤數，沒有把協同組數乘以虛構活化係數。

## 關聯與進步規則

- `MUSCLE_ROLES` 明列 primary/support。15 區含胸大肌、三角肌、肱二頭肌、肱三頭肌、前臂、腹部核心、腹斜肌、上背、背闊肌、豎脊肌、臀部、股四頭肌、腿後、小腿與大腿內收肌群。
- 本版未把握法、角度、單側或動作幅度納入紀錄；主要／協同是預設關聯，不是 EMG 或完整肌肉活化估計。不同動作變式未經量測不可假裝已知。
- 使用 `analyze.exercises` 的已篩选投影；已刪除、未解決衝突與日期外紀錄不進入本視圖。單筆選取只影響本次訓練模式。
- 同一筆可對應多區，各區算一次原始組數。區域組數不可加總成全身總組數。
- 按 `[exerciseId,machine,unit]` 分组，比較每組最近兩筆，沿用 `compareSessions` 的逐組、機台、單位、組數與輔助方向規則；不跨機台取重量。
- 只有主要關聯動作參與肌群的進步色。協同關聯仍在明細顯示，不把整個手臂染成胸推進步。
- 全部主要動作組別均可比且進步才顯示進步；部分資料不足或方向不同顯示不一致；全部不足顯示不足。主要比較中的疼痛／動作未知或事件旗標優先顯示需檢視。
- 每條器材明細列出前後兩筆日期、每組重量／輔助量與次數、判定原因。這是最近兩筆的動作表現，不宣稱長期肌力趨勢、肌肥大或平台期。
- 人體圖與訓練進程共用 `training-streams.js`。每區顯示可比組別數／全部組別數；不能用單一器材進步掩蓋其他組別不足。

## 哪塊值得練／追蹤

「期間重點」依整個日期範圍計算，不受目前檢視的單一器材影響。點選候選部位會清除器材篩選並移至該部位明細。展開可選：

- 建立主要訓練基準：整個日期範圍內沒有主要關聯組數，且動作目錄有對應主要訓練。僅協同不等同主要基準。
- 已有可比進步：該區主要關聯的所有器材組別都有可比進步。
- 先查看紀錄：相關動作出現疼痛或技術事件；旗標沒有疼痛位置，不能理解為該肌肉受傷。

目前未設定個人訓練目標或教練計畫，因此這些是記錄與安排訓練的候選清單，不是自動處方。沒有用「幾天沒練」假定恢復程度，也沒有把沒資料判為弱點。

## 尺寸的決策

人體幾何比例固定。組數、重量與表現增加不改變肌肉面積，避免把進步誤讀為肌肥大。

實際尺寸若要比較，建議未來獨立增加：量測日期、部位、左右、圍度 cm 與量測條件；用同部位前後點線／長條呈現。現有資料沒有圍度，本版未新增圍度輸入或合成個人體型。InBody 保留原本數值卡與趨勢，不把部位量測拆成單肌肉大小。若做左右量測比較，需同日、同指標、同單位；不能混用部位除脂量、肌肉量與圍度。

## 模組邊界

| 模組 | 唯一責任 |
|---|---|
| `domain/muscles.js` | 動作與肌群角色表、原始組數統計 |
| `domain/body-insights.js` | 篩選、器材組別、比較聚合、候選部位 |
| `ui/body-geometry.js` | 肌群、外形、肌束與骨架座標 |
| `ui/body-drawing.js` | SVG 與資料色彩、部位互動 |
| `ui/body-detail.js` | 原始證據明細、下一步清單 |
| `ui/body-map.js` | 圖層與篩選狀態、元件組裝、組數長條 |
| `ui/body-map.css` | 專用樣式與手機排版 |

未改 Google 欄位、儲存格式或同步協定，舊紀錄直接適用。service worker v3 增列所有新模組。換圖稿不需改統計；調整角色表不需動同步。

## 校準後的互動與新增資料

選單保留原生 DOM 節點；點部位只更新圖與明細，不重建控制項或重算全部統計。展開狀態、圖／清單選擇、前後面与骨架狀態可跨同頁資料重繪保留。手機圖上方的選取摘要停留於可見位置，並可跳至明細。數值清單提供至少 44px 高的按鈕與文字狀態；顏色不是唯一資訊。小腿後側只在背面上色，從清單選取會切至背面。

進步證據列出日期、組數、總次數、負荷、疼痛、技術狀態、原始備註與待核對原因；第一次有旗標的紀錄也不能因為不足兩筆而隱藏。無資料時提示記第一筆，不列出整張人體為待補練部位。

新增上斜胸推、二頭彎舉、髖內外展、V-Squat；新增大腿內收區。Hip Abduction 仍為臀肌群的大區域關聯，沒有宣稱量測到臀中肌活化。

InBody 新增同日左右 Lean 長條、原始值歷史、起點至最近差值、待核對值獨立標示。圖形不因肌肉量或組數縮放；缺值不補零。原始報告的評分、水分、代謝與部位參考比可展開查看。這些是量測呈現，不取代功能與力量測試。

額外模組：`domain/comparison.js` 負責兩筆比較，`domain/training-streams.js` 負責分組與聚合，`ui/body-controls.js` 維持控制項狀態，`ui/body-regions.js` 呈現部位清單／長條，`ui/training-evidence.js` 共用比較證據，`ui/record-quality.js` 編輯核對設定，`ui/body-composition.js` 呈現量測。資料來源與旗標的契約見 schema.md。

手機操作校準參考 [W3C 使用顏色](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html)與[目標尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)；目前只有指定案例驗證，不宣稱全面 WCAG 認證。
