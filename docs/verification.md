## 真正瀏覽器流程

使用 Windows Microsoft Edge Chromium 的獨立設定檔，412 × 915 viewport、觸控／mobile 模式；本機 HTTP 以 `/rehab/` 子路徑測試 GitHub project Pages 路徑。

1. 新增訓練，重載後修改，確認真正 IndexedDB 保存。
2. 沿用上次產生新紀錄，不修改原始紀錄。
3. InBody 只填體重，其他測量仍為缺漏。
4. 透過頁面下載備份並再次匯入，版本不重複。
5. service worker 控制頁面後，斷網重載、新增、再重載仍可讀取。
6. 刪除後重載，墓碑生效且歷史保留。
7. 412px 頁面無水平溢出、沒有未處理的 JavaScript 錯誤；已檢視截圖。
8. 真實 UI → GIS adapter → sync engine → Sheets adapter → IndexedDB 串接；外部 GIS／HTTP 回應由測試控制。
9. 全新瀏覽器設定檔，從受控 Sheet 載入相同紀錄。
10. 兩個隔離設定檔離線修改同筆，恢復同步顯示衝突，選擇版本並讓另一設定檔讀回一致內容。
11. 兩個真正 IndexedDB 連線同時寫入，兩筆提交均保存。
12. 字體放大至 200%，頁面與訓練 dialog 在 412px 仍無水平溢出。

測試程式只替代 Google 外部回應，未替代 domain、儲存、同步或 UI 的 production code。這比 mock-only 單元測試多驗證模組間串接，但**仍不能證明真實 Google 服務、OAuth 設定或遠端持久化正常**。

截圖與測試紀錄在被 Git 忽略的 `artifacts/`。這些是虛構測試資料，不是使用者健身紀錄。

加入人體圖後重新執行上述兩支瀏覽器測試；已檢視正面／背面截圖，並重新檢查模組、Dashboard 串接及離線資產清單。人體圖只呈現動作關聯覆蓋，沒有證據可支持部位肌力或疼痛位置判讀。

## 審查修正與限制

- Google 批次附加可能中途失敗。同步引擎先依因果順序排列待送版本，使每個成功寫入的前綴都包含父版本。相同版本物理重複列仍可能存在，UI 依 ID＋內容去重，不宣稱 exactly-once。
- 同日優先採選填的台灣 time；缺少時間排在該日已填時間前，再依首次建立時間與 ID 排序。這是顯示排序，不代表未知紀錄的實際發生先後；日期、時間可補登，不自行推測。
- 手機資料綁定單一 Sheet，沒有加入跨資料集切換或自動合併不同帳號資料。
- GitHub 部署只使用允許清單的網站檔案；Google 權杖只留記憶體，測試備份與模擬權杖不包含於部署資產。

## 舊快取入口更新修正

使用者回報私人新版入口只顯示「版本類型不正確」。已以真實 cache-first Service Worker 與舊版不接受 rehab 的驗證器重現：入口 HTML 從網路取得，但其靜態 import 仍載入舊快取。先前的全新瀏覽器案例不足以驗證此更新情境。
